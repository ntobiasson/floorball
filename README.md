# Peleille

Online registration for the team's floorball sessions, plus 25 years of play
history. Replaces an application that ran on an unmaintained Lotus Domino
server.

- **Registration** is open on **Monday, Wednesday and Saturday**, and only for
  the current day. Any other day shows a "not a game day" screen.
- **No accounts.** Anyone can register anyone, by picking a previous player or
  typing a new name, and anyone can remove a name.
- **The 25-year history** is at `/peliaktiivisuus`, the second of the two
  tabs. The archive is the reason this project exists — the Domino server is
  being switched off — so it is preserved in full. The page filters it by name
  and by year and orders it by name or by games played; choosing a year ranks
  everyone by that year alone. It also shows through on the registration form,
  which suggests previously seen names from the imported player directory.
- **Announcements** are written and deleted at `/tiedotteet`. Nothing links
  there, but the address is an obvious one and there is no password: anyone
  who visits the site can manage them, as anyone can already add or remove any
  name.
- **Writing needs a Cloudflare Turnstile check.** Registering a name and
  managing announcements each carry a token the API redeems with Cloudflare
  before the handler runs. It identifies nobody and asks nothing of the
  visitor — the widget solves itself — it only keeps scripts off the three
  write endpoints. Reading is untouched, and removing a name is not gated.

## Stack

TypeScript throughout. React + Vite for the SPA, a single Node 24 Lambda
running Hono for the API, DynamoDB for storage, and one CloudFront
distribution in front of both so there is no CORS anywhere. All infrastructure
is AWS CDK.

| Package | What it is |
| --- | --- |
| `packages/shared` | Date rules, name normalization, Zod schemas. Consumed as TypeScript source. |
| `packages/api` | Hono routes and the DynamoDB repository. `handler.ts` is the Lambda entry; `serve.ts` is for local use only. |
| `packages/web` | The SPA: the day's list and an unlisted announcements page. All imagery is inline SVG — no raster assets. |
| `packages/infra` | The CDK stack. |
| `packages/import` | One-off extraction of the history out of Domino. |
| `e2e` | Playwright smoke flow against a real API and DynamoDB. |

## Local development

Requires Node 24 (`.nvmrc`) and Docker.

```sh
npm ci
docker compose up -d                       # DynamoDB Local on port 8001

# Create the table and fill it with a few real players.
TABLE_NAME=sahlykanta-local DYNAMODB_ENDPOINT=http://127.0.0.1:8001 \
  npx tsx e2e/seed.ts

# One terminal: the API.
TABLE_NAME=sahlykanta-local DYNAMODB_ENDPOINT=http://127.0.0.1:8001 \
  AWS_REGION=eu-north-1 AWS_ACCESS_KEY_ID=local AWS_SECRET_ACCESS_KEY=local \
  PORT=3400 npm run serve -w @sahlykanta/api

# Another: the SPA. Open http://127.0.0.1:5273
API_ORIGIN=http://127.0.0.1:3400 npm run dev -w @sahlykanta/web -- --port 5273
```

Vite proxies `/api` to the API, mirroring the single CloudFront origin used in
production, so there is no CORS locally either.

The seed is an invented sample generated by `e2e/seed.ts` and loaded through
the production loader: five players spanning 2001 to 2026. It is invented but
shaped like the real archive — a long-standing player beside a rare one, the
`(EHKÄ)` duplicate that must stay its own player, somebody who stopped in
2009 and survives only in the directory, and Torstai games from before the
schedule settled on Mon/Wed/Sat. No real player's data is in this repository.
One game falls on 19.10.2026, so the day's list does not start empty.

Add `FAKE_TODAY=2026-10-20` to the API's environment to see the
not-a-game-day screen without waiting for a Tuesday. It is read only by
`serve.ts`, which is never deployed. Today is rarely a game day, so
`FAKE_TODAY=2026-10-19` is the quickest way to get the registration form —
and the Turnstile widget — on screen at all.

**Turnstile, locally.** Nothing to configure. The real widget is registered
for the deployed hostname only, so the dev server pairs Cloudflare's published
testing sitekey (`packages/web/.env.development`) with its published
always-passes secret (`packages/api/src/serve.ts`). The widget renders for
real, marked "For testing only", and every token is accepted. Neither value is
a credential; both are in Cloudflare's documentation, and the Lambda refuses
to start if it ever finds one of them in production.

That also means a bogus token is accepted locally — the always-passes dummy
accepts anything. To watch the refusal path instead, start the API with
`TURNSTILE_SECRET=2x0000000000000000000000000000000AA`, the always-fails
dummy, and every write comes back 403.

**Deploying your own copy.** `packages/web/.env.production` holds this
project's Turnstile sitekey. A sitekey is public — it is in the page source on
every visit — but it is registered for this deployment's hostname only, so on
your own distribution the widget will not render and every write will fail the
check. Create a widget for your hostname, put its sitekey there, and put its
secret in Secrets Manager; `docs/runbook.md` has the steps.

**On ports.** DynamoDB Local is published on **8001** and these examples use
**3400** and **5273** rather than 8000/3000/5173, which are routinely occupied
on a development machine — and a clash there is quiet and confusing, because
the client happily talks to whatever is listening. Change them freely if they
are taken on yours.

## Checks

```sh
npm run lint
npm run typecheck
npm test        # 422 unit and integration tests; needs docker compose up
npm run e2e     # Playwright, starts its own servers
```

`npm run typecheck` runs three passes: the root packages, then `packages/infra`
and `packages/web`, which need their own compiler settings (CDK's types are not
written for `exactOptionalPropertyTypes`; web needs JSX and the DOM lib).

## Importing the history from Domino

See [docs/runbook.md](docs/runbook.md). In short:

```sh
cd packages/import
# --url is required and has no default: the activity view to walk.
export DOMINO_URL=http://<domino-host>/<db>.nsf/peliaktiivisuus.xsp

npx tsx src/cli-scrape.ts --limit 5          # always dry-run first
npx tsx src/cli-scrape.ts                    # the full walk, ~2.5 hours
npx tsx src/cli-scrape.ts --resume           # after an interruption
TABLE_NAME=<table> npx tsx src/cli-load.ts --out ./out
```

The scraper only ever talks to `peliaktiivisuus.xsp`, which has no write
controls. It refuses any other URL by construction, and it refuses to follow
redirects, because a POST to `pelit.xsp` would create a real registration on
the live system.

Both output files are written as each player completes, so an interruption
keeps what it had already proved. Correctness rests on two checks: per-player
counts against what Domino prints, and the harvested player set against the
collapsed index — the second because the first cannot see a player the walk
never reached. **Load before anyone starts using the app**; the loader refuses
to overwrite totals that live registrations have already moved.

## Deploying

Pushing to `main` deploys via GitHub Actions using OIDC — there are no AWS keys
in this repository. Until these are set the deploy job **skips** rather than
failing, and says in the run summary which are missing:

| Name | Kind | Example |
| --- | --- | --- |
| `AWS_DEPLOY_ROLE_ARN` | secret | `arn:aws:iam::123456789012:role/floorball-deploy` |

There is **no custom domain**: the app answers on the address CloudFront gives
the distribution, and the deploy prints it in the run summary. That removes the
hosted zone, the certificate and the DNS records — nothing to renew, nothing to
pay a registrar. The stack defaults to `eu-north-1` (override with
`SAHLYKANTA_REGION`, before the first deploy); CloudFront is global regardless.
At this traffic every service stays inside the free tier, and a budget alarm —
created by `scripts/create-budget.sh`, since AWS Budgets only exists in
`us-east-1` — covers the rest.

Before the first deploy, bootstrap the account and create the OIDC deploy role:

```sh
npx cdk bootstrap aws://<account>/eu-north-1
REPO=<owner>/<repo> ./scripts/create-deploy-role.sh
BUDGET_EMAIL=you@example.fi ./scripts/create-budget.sh
```

No AWS access key is ever created; GitHub's OIDC token is traded for temporary
credentials per run. See the runbook for what the role may and may not do.

## Privacy, security, contributing

The deployed app holds real people's names and the dates they played, going
back to 2001. **None of that data is in this repository.** The import output is
gitignored and a CI job fails the build if it is ever committed; every name in
the tests and the local seed is invented.

There is no authentication anywhere in this application, by design — see
[SECURITY.md](SECURITY.md) for the full threat model and how to report
something privately. [CONTRIBUTING.md](CONTRIBUTING.md) covers running the
suite and what gets declined.
